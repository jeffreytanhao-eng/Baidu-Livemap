# 路演口播稿（3 分钟）

节奏约 450–500 字/分钟，全文约 1450 字。【】内为操作步骤，括号内为备用提示。演示前：起 API 与 Web（`scripts/dev.ps1`），浏览器 1920×1080 全屏打开 http://localhost:3000，确认右上角「演示数据」角标在。

---

## 第一段：直线圆的误导（0:00–0:40）

【页面打开即自动出劲松 15 分钟结果；打开图层面板，勾开「直线对照圆」】

各位老师好。市面上很多「15 分钟生活圈」，其实是在地图上扣一个圆。大家看这个灰色虚线圆——它穿过了住宅楼，跨过了大片水域，还压上了东二环、东三环快速路。人不会穿墙，不会淌水，也不能走上封闭汽车道。这个圆告诉居民「步行 15 分钟可达」的地方，有三分之二其实是走不到的。

我们的产品回答的是另一个问题：**从家门口出发，沿着真实路网，15 分钟真正走得到哪里**。答案就是屏幕上这块青色的斑。

## 第二段：穿不过的与进得去的（0:40–1:30）

【地图平移到西侧水域，指水对岸】

请看西边这片水域：等时斑在河边整齐断开，**只从桥的位置续到对岸**——这是图层面的硬约束，不是画出来的。

【指住宅楼（灰色块）】

这些灰色多边形是住宅楼，系统判定为「不可进入」，斑绕着它走，外墙还留了 1.5 米墙厚。

【指北京富力广场（青色块）】

而这栋青色的北京富力广场是「可进入建筑」——人可以穿行大厅和底商，所以斑允许覆盖它，穿行速度按 1.1 倍步行折算。

【指劲松大厦（青色描边）】

旁边这栋劲松大厦是第三种情况：底商可进、楼上不可。系统只生成沿外墙内侧 8 米的底商廊道，绝不穿楼心。建筑可进入性分成四类，这是和「插值糊一个斑」最本质的区别。

## 第三段：X 分钟与缺口（1:30–2:20）

【依次点顶栏 5、20，每次点后停 1 秒指按钮旁「参数已改，尚未体验」提示与报告水印，再点「开始体验」】

分钟数是可配的：5、10、15、20 快捷档，也可以自定义 5 到 30。注意一个细节——改了参数**不会**自动重算，按钮旁会亮「参数已改」，报告区打上「以下为上次结果」水印，必须点「开始体验」。这样评委连续操作时，每一张图对应哪一组参数永远说得清。

【20 分钟结果出来后，指圈层】

四层等时圈来自**同一次**带截止的 Dijkstra 搜索，不为每层各跑一遍。劲松这个点，15 分钟冷算半秒左右，缓存命中 1 毫秒。

【指向报告栏「1km 步行盲区速览」】

再看 1 公里盲区：便利生活、医疗保障、学习教育三类，各有百分之多少的网格里走不到。注意网格范围是**固定的 1 公里**，不随 X 缩放——但每格「走不到」的判定跟着分钟走：从 15 调到 20 分钟，部分格子里的设施变得可达，占比会从 100% 降到 86%。

## 第四段：扇区指认与收尾（2:20–3:00）

【指向报告栏「扇区缺口」】

最后是扇区缺口。八个方向对比等时斑和直线圆的面积：西向八成面积走不到——因为**被水域和东二环切断，需绕行**。系统不只是报个数，而是按 100 米里程采样水域与快速路几何，把阻隔物名称挂到具体方位（东侧各扇区标「东三环」、20 分钟档南侧还会出现「京津城际线」），诊断句句首还会标出对应方位。

【指报告顶部】

综合分、面积比、硬三项达标，全部来自计算结果；报告可以打印、下载 JSON、复制带参数的分享链接。

【停顿，收尾】

一句话总结：别人画「理论上能到哪」，我们画**「人真正走得到哪」**——不穿墙、不淌水、不上快车道，商场进得去、住宅绕得开。代码 MIT 开源，本地两条命令即可复现。谢谢。

## 备用问答预案

- **数据从哪来？** 路网/建筑/水域来自 OpenStreetMap（ODbL），仓库内置预裁包；POI 与步行校准走百度服务端 API，底图展示用百度 JS API GL。
- **没有 AK 能跑吗？** 能。`DEMO_MODE=true` 走快照与确定性合成设施，全流程可演示（即当前演示状态）。
- **百度提供了什么？** 底图、POI 检索、DirectionLite 步行折线（注入为高权边补底图缺口）、RouteMatrix 耗时校准（第三拍异步，不挡主圈）。
- **为什么不用官方等时圈？** 该接口未对公众 AK 开放；系统保留了开关，无权限时明确降级并标注「以自建引擎为准」。
- **别的城市？** 白名单六城（京/沪/杭/蓉/穗/深）完整体验；名单外允许计算，界面标「方法验证」。
