# 达标明细悬停显示具体设施 + 解释小学「3 所却缺口」

## Summary

1. 在「达标明细」表中，鼠标悬停任一类别行（如菜市场）时弹出一个跟随光标的浮层，列出该类具体设施：名称 + 步行分钟（+ 圈内/圈外徽标），数量与「最近步行」值和表格列严格一致。
2. 向用户解释劲松「小学 3 所却显示缺口」的原因——这是口径设计使然，不是 bug：**达标只看最近一所的步行时间 ≤ X 分钟，与数量无关**（3 所小学最近的那所也要走 21.7 分钟 > 15 分钟）。不改代码。

## Current State Analysis

- 前端「达标明细」表在 [ReportPanel.tsx](file:///d:/项目/上海百度/apps/web/components/report/ReportPanel.tsx#L253-L294)：每行渲染 `coverage.categories` 的 `count / nearestMinutes / passed`，无任何悬停信息。
- **悬停数据已在前端，无需后端改动**：`CheckupResponse.pois: Poi[]`（[types.ts](file:///d:/项目/上海百度/apps/web/lib/types.ts#L40-L48)）每项含 `name / category / walkMinutes / within / estimated?`。
- **一致性已由后端保证**：[coverage.py](file:///d:/项目/上海百度/apps/api/app/coverage.py) 中 `compute_coverage` 的 `count`（L187）与 `nearestMinutes`（L182-183，取 `_raw` 最小值）与序列化返回的 `pois` 来自**同一份 `poi_views`**，数字天然对得上。
- **一个口径细节**：吸附失败的 POI 走直线估算（`estimated=true`，`_raw=None`），**不参与** `nearestMinutes` 计算（L182 只取 `_raw` 非 None），但其 `walkMinutes`（直线估算值）可能比真最近值更小。悬停列表若按分钟排序把这些排前面，首行就与「最近步行」列对不上。
- 小学缺口语义：[category_passed](file:///d:/项目/上海百度/apps/api/app/coverage.py#L101-L107) —— 除 `daily`（需 ≥3 处且最近达标）、`elderly`（有即达标）外，其余类别 `passed = nearest ≤ minutes`。

## Proposed Changes

### 改动 1：ReportPanel.tsx 达标明细行悬停浮层（唯一代码改动）

文件：[apps/web/components/report/ReportPanel.tsx](file:///d:/项目/上海百度/apps/web/components/report/ReportPanel.tsx)

1. **新增 state**：`const [hoverCat, setHoverCat] = useState<{ id: PoiCategory; x: number; y: number } | null>(null);`
2. **表格行绑定事件**：`coverage.categories.map(...)` 的 `<tr>` 上加
   - `onMouseEnter={(e) => setHoverCat({ id: c.id, x: e.clientX, y: e.clientY })}`
   - `onMouseMove={(e) => setHoverCat((p) => (p && p.id === c.id ? { ...p, x: e.clientX, y: e.clientY } : p))}`
   - `onMouseLeave={() => setHoverCat(null)}`
   - 行加 `cursor-default` 提示可悬停。
3. **浮层渲染**（表格后、`CardBody` 内，`position: fixed` 跟随光标，避免被 Card/表格裁剪）：
   - 数据：`const pois = result.pois.filter((p) => p.category === hoverCat.id).sort((a, b) => a.walkMinutes - b.walkMinutes);` 同时把 `estimated=true` 的条目**排到列表末尾**（排序 key：`estimated ? 1 : 0` 优先），保证首行 = 表格「最近步行」列的值。
   - 结构：宽约 240px 圆角白卡（`bg-white border border-slate-200 shadow-lg rounded-md`，`z-50`，`pointer-events-none`）：
     - 头部：`{c.name} · {c.count} 处`（count 直接取当前行的 `c.count`，与「数量」列必然一致）；
     - 列表：`max-h-56 overflow-y-auto`，每行 `名称 …… X.X 分`，后附小徽标：`within ? 绿「圈内」: 灰「圈外」`；`estimated` 的条目分钟值前加「约」并标「直线估算」；
     - 定位：`style={{ left: x + 14, top: y + 12 }}`；简单防溢出：`left = Math.min(x + 14, window.innerWidth - 260)`。
4. **不再加任何图例/说明文字**（遵循用户此前「删描述」的偏好）。

### 改动 2：小学「3 所却缺口」——仅解释，不改代码

直接向用户说明（本次会话回复，无代码改动）：

- 「数量」= 在中心周边检索到、通过清洗去重后的该类设施总数（圈内 + 圈外都算）；
- 「达标」= **最近一所**的步行时间 ≤ 当前分钟数（15 分钟体验即 ≤15 分钟），数量不参与判定（仅 `daily` 日常购物额外要求 ≥3 处，`elderly` 养老有即达标）；
- 劲松案例：检索到 3 所小学，但最近的一所步行 21.7 分钟 > 15 分钟阈值 → 判「缺口」。这恰恰是该产品要暴露的问题：学校不远不等于步行可达（被快速路/铁路阻隔或实际很远）。

## Assumptions & Decisions

- 浮层用 React state + fixed 定位，不用原生 `title`（不支持多行/样式）也不用 CSS-only（`<tr>` 相对定位跨浏览器表现不一致）。
- 距离单位用「步行分钟」而非米，与表格「最近步行」列及全站口径一致。
- 浮层内数量用行数据 `c.count`、排序排除 estimated 干扰首行，双保险保证「与列表里的数量和步行时间匹配」。
- 不动后端、不动其它卡片。
